# HappyPC Питер

Многостраничная дизайн-концепция компьютерной мастерской HappyPC Питер. Редакционная сетка, нейтральная палитра с фирменным акцентом, фотографии процесса и готовых систем, технические кейсы и оригинальный логотип петербургского Telegram-канала. Единый файл оформления — `src/studio.css`. Источники логотипов — `scripts/brand-sources.json`. Vanilla JavaScript + Vite. Работает как статический сайт, в том числе в подкаталоге GitHub Pages.

## Локальная работа

```sh
npm ci
npm run dev
```

```sh
npm run check
npm run build
npm run preview
```

## Что готово

- Главная с фотографиями мастерской, подробной конфигурацией проекта, перечнем сборок, направлениями ремонта и техническими кейсами.
- Каталог: фильтры, поиск, сортировка, полноценные страницы четырёх конфигураций.
- Галереи с управлением с клавиатуры, модальные контакты.
- Четыре направления ремонта, выбор симптомов, подготовка обращения.
- Пошаговый подбор ПК с черновиком в sessionStorage, итоговым сообщением и копированием.
- Пять реальных кейсов со ссылками на публикации, страница мастерской, контакты, три полезные статьи.
- Адаптивность, доступная клавиатурная навигация, reduced-motion, локальные шрифты, WebP-изображения.

## Обращения

Сайт не отправляет сообщения автоматически и не имитирует отправку заявки. В подборе и ремонте создаётся текст: посетитель может скопировать его или открыть Telegram и отправить самостоятельно. Для сохранения и обработки заявок внутри сайта нужен отдельный согласованный сервис.

## Данные и фотографии

Источники: публичные публикации `https://t.me/HappyPC_Piter` и официальный сайт `https://happypc.ru/`. Исходные описания и адреса фотографий сохранены в `scripts/asset-sources.json`. На страницах компьютеров и кейсов есть ссылки на конкретные публикации. Цены — исторические значения из публикаций, не подтверждение актуального наличия.

Перед официальным запуском согласовать с компанией тексты, использование фотографий, актуальный ассортимент, реквизиты и условия. Вымышленные отзывы, сотрудники и цифры не добавлены.

## GitHub Pages

Готов workflow `.github/workflows/pages.yml`. Опубликуйте проект в GitHub-репозитории с основной веткой `main`, выберите Settings → Pages → Source: GitHub Actions. Workflow соберёт и опубликует `dist`. Маршруты используют hash-навигацию и не требуют серверных перенаправлений. Поле `base: './'` поддерживает project Pages.

Шрифты Golos Text и Oswald распространяются по SIL Open Font License. Лицензии находятся в `public/fonts/`.
